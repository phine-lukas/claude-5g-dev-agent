## 5.15A UE level measurement (De)Activation

### 5.15A.1 General

A UP function that supports UE level measurements shall set the ULM flag in the UP Function Feature IE. If so, the UP function shall support being instructed to activate/deactivate UE level measurement only, as specified in this clause and in clause 5.15A.2.

A UP function that supports UE level measurements shall also support per QoS flow per UE QoS monitoring for packet delay (see clause 5.39) and so shall also indicate its support of the QFQM feature in the UP Function Feature IE.

If the UP function additionally supports Signalling based Trace, the UP function shall also set the TRACE feature flag in the UP Function Feature IE as specified in clause 5.15, in which case the UP function shall support being instructed to activate/deactivate any of the following:

\- trace only, as specified in clause 5.15; or

\- both trace and UE level measurement, as specified in this clause and in clause 5.15A.3.

Upon receiving a request to start collecting UE level measurements (see 3GPP TS 32.422 \[35\]), the CP function shall activate UE level measurements in the UP function as specified in clauses 5.15A.2 (for UE level measurements only) and 5.15A.3 (for both signaling based trace and UE level measurements). Additionally, the CP function shall create one new SRR to activate QoS flow related QoS monitoring for packet delay for UE level measurements in the UP function as specified in clause 5.39.3.2 with the following additions:

\- the SRR shall include the Reporting Control Information IE indicating that the measurements are requested to be reported (as UE level measurements, as defined in clauses 5.15A.2 and 5.15A.3) to the trace collection entity.

\- the SRR shall include the QoS Monitoring per QoS flow Control Information IE with:

\- the QFI IE(s) indicating the QoS flow(s) for which UE level measurements are to be performed (e.g. for the default QoS flow, all QoS flows or specific QoS flows based on local policy at the SMF);

\- the Requested QoS Monitoring IE requesting to measure the DL packet Delay, UL packet delay and/or Round Trip Packet Delay according to the requested UE level measurements;

\- the Reporting Frequency IE set to "Periodic" reporting; and

\- the Measurement Period IE set to a period equal or smaller than the time period of UE level measurements.

NOTE: The CP function creates one new SRR as described above even if QoS flow related QoS monitoring for packet delay was already activated in the UP function for the same QoS flows for other reasons than UE level measurements, e.g. if QoS monitoring had been requested in a PCC rule received from the PCF.

Upon being instructed to perform UE level measurements, the UP function shall perform the requested UE level measurements whenever an SRR with QoS flow related QoS monitoring for packet delay with the Reporting Control Information IE indicating UE level Measurement is provisioned at the UP function for the corresponding measurements. When no such SRR is provisioned at the UP function, the UP function shall store the UE level measurement control information and wait until QoS flow related QoS monitoring for packet delay with the Reporting Control Information IE indicating UE level Measurement is provisioned.

The UP function shall report the QoS monitoring results of the QoS flows as UE level measurements to the trace collection entity as specified in 3GPP TS 32.422 \[35\].

Upon receiving a request to stop collecting UE level measurements (see 3GPP TS 32.422 \[35\]), the CP function shall deactivate UE level measurements in the UP function as specified in clauses 5.15A.2 (for UE level measurements only) and 5.15A.3 (for both signaling based trace and UE level measurements). Additionally, the CP function shall instruct the UP function to stop performing QoS flow related QoS monitoring for packet delay for UE level measurements, as specified in clause 5.39.

### 5.15A.2 UE level measurement only (De)Activation

If the UP function indicated support of UE level measurement by setting the ULM feature flag in the UP Function Features IE, the CP function may activate UE level measurement only (i.e. without trace) during a PFCP session establishment or a PFCP session modification procedure, by including the Trace Information IE and UE Level Measurements Configuration IE with the following information in the PFCP Session Establishment Request or PFCP Session Modification Request:

\- Trace Information IE: including MCC, MNC, Trace ID, Session Trace Depth and IP Address of Trace Collection Entity. Triggering Events and List of Interfaces shall not be included, so the Length of Triggering Events and the Length of List of Interfaces shall be set to 0.

\- UE Level Measurements Configuration IE: including Job Type with value "5GC UE Level Measurements only", Measurement Types and Time Period.

For Streaming based Reporting as defined in 3GPP TS 32.422 \[35\], the CP function may also include the Trace Collection Entity URI IE in the PFCP Session Establishment Request or PFCP Session Modification Request.

The CP function may deactivate an on-going UE level measurement only (i.e. without trace) by including the Trace Information IE with a null length in a PFCP Session Modification Request.

There shall be at most one UE level measurement activated per PFCP session at a time. If the UPF does not support one or more the requested Measurement Types, the UPF shall ignore the unsupported measurement types and shall not perform UE level measurements for the unknown Measurement types.

### 5.15A.3 Signalling based Trace and UE level measurement (De)Activation

If the UP function indicated support of Trace by setting the TRACE feature flag and support of UE level measurement by setting the ULM feature flag in the UP Function Features IE, the CP function may activate both signaling based trace and UE level measurement during a PFCP session establishment or a PFCP session modification procedure, by including the Trace Information IE and UE Level Measurements Configuration IE in the PFCP Session Establishment Request or PFCP Session Modification Request. For Streaming based Reporting as defined in 3GPP TS 32.422 \[35\], the CP function may also include the Trace Collection Entity URI IE in the PFCP Session Establishment Request or PFCP Session Modification Request. The UE Level Measurements Configuration IE shall then include the Job Type with value "Trace and 5GC UE Level Measurements".

The CP function may deactivate an on-going UE level measurement and keep the on-going trace session by including the UE Level Measurements Configuration IE with a null length in a PFCP Session Modification Request.

The CP function may deactivate an on-going trace session and keep the on-going UE level measurement by including the Trace Information IE and UE Level Measurements Configuration IE with the following information in a PFCP Session Modification Request:

\- Trace Information IE: including MCC, MNC, Trace ID, Session Trace Depth and IP Address of Trace Collection Entity. Triggering Events and List of Interfaces shall not be included, so the Length of Triggering Events and the Length of List of Interfaces shall be set to 0

\- UE Level Measurements Configuration IE: including Job Type with value "5GC UE Level Measurements only", Measurement Types and Time Period.

The CP function may deactivate both on-going trace session and UE level measurement by including the Trace Information IE with a null length in a PFCP Session Modification Request.
